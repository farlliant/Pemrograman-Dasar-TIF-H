## 🔄 Siklus Praktikum

Setelah dua bab materi selesai dipelajari, pertemuan berikutnya digunakan untuk **Live Coding** yang menguji pemahaman terhadap kedua bab tersebut.

```text
Bab 00
  ↓

Bab 1
  ↓
Bab 2
  ↓
Live Coding 01

Bab 3
  ↓
Bab 4
  ↓
Live Coding 02

Bab 5
  ↓
Bab 6
  ↓
Live Coding 03
```

Dengan pola tersebut:

```text
2 Bab Materi
      ↓
Live Coding
      ↓
2 Bab Materi
      ↓
Live Coding
      ↓
...
```

Live Coding digunakan untuk mengevaluasi kemampuan mahasiswa dalam memahami permasalahan, menyusun logika, mengimplementasikan program, dan menghasilkan output sesuai spesifikasi.

## 🔒 Repository & Assessment Policy

Repository ini bersifat **public** dan digunakan untuk dokumentasi materi yang telah diperbolehkan untuk dipublikasikan.

Material evaluasi internal seperti:

```text
Draft soal
Hidden test cases
Bank soal
Rubrik penilaian internal
Solution sebelum pelaksanaan
Soal Live Coding yang belum dirilis
Soal UTP/UAP yang belum dirilis
Materi remedial yang belum digunakan
```

tidak disimpan pada repository public.

Material internal disimpan secara terpisah dan tidak dilacak oleh Git melalui konfigurasi `.gitignore`.

Contoh struktur lokal:

```text
_private/
│
├── Live Coding/
│   ├── LC-01/
│   ├── LC-02/
│   └── LC-03/
│
├── UTP/
│
├── UAP/
│
├── Bank Soal/
│
└── Remedial/
```

Folder `_private/` tidak termasuk dalam repository GitHub.

Soal dan penyelesaian Live Coding, UTP, maupun UAP hanya dapat ditambahkan ke repository setelah evaluasi selesai dan material tersebut diperbolehkan untuk dipublikasikan.

## 🛠️ Konvensi Repository

Penamaan folder utama:

```text
Bab X/
Live Coding/
Ujian Praktikum/
```

Penamaan commit mengikuti pola yang konsisten.

Contoh:

```text
feat(bab-2): add BMI classification assignment
docs(bab-2): update selection condition documentation
docs(lc-01): add live coding problem
feat(lc-01): add live coding solution
docs(utp): add practical exam documentation
chore: update gitignore
```

Prefix yang umum digunakan:

| Prefix | Digunakan untuk |
|---|---|
| `feat` | Source code atau fitur baru |
| `docs` | Dokumentasi atau README |
| `fix` | Perbaikan kode |
| `refactor` | Perubahan struktur tanpa mengubah fungsi utama |
| `chore` | Konfigurasi repository dan maintenance |
